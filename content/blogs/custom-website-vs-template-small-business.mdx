"Should I build a custom website or just use a template?" is the first question most small businesses ask, and the honest answer is that it depends on what the site has to do. Here is how I think about it, without pretending one option always wins.

## What "template" and "custom" actually mean

A **template site** is built on a platform such as WordPress, Wix, Squarespace or Shopify, using a ready-made theme. You pick a layout, change the text and images, and add features through plugins or apps.

A **custom website** is designed and coded for your specific pages and goals. No theme sits underneath it. The developer decides what loads, what the layout does at each screen size, and how the forms and tracking work.

Neither is "real" and the other "fake". They trade money against control.

## Where a template wins

- **Cost and speed to launch.** A theme and a weekend can get a simple site live. A custom build takes planning and development time.
- **You edit it yourself.** Page builders let non-technical owners change text and swap images without a developer.
- **Standard needs.** A five-page brochure site, a basic shop or a portfolio rarely needs anything bespoke.

If that describes you, a template is a sensible choice. Starting there and moving to custom later is a perfectly good plan.

## Where custom wins

**1. Page speed.** Template sites commonly ship a theme, a page builder and several plugins on every page, whether that page uses them or not. That extra JavaScript and CSS is the usual reason a template site scores badly on mobile. A custom page loads only what it needs. If you are already fighting a slow site, read [why a website is slow on mobile](/blog/why-is-my-website-slow-on-mobile) first, because the cause is often fixable without a rebuild.

**2. A specific conversion flow.** A landing page for paid ads has one job and one action. Themes are built to be flexible for everyone, which usually means more menus, more sections and more choices than a focused page wants. The [lessons from building 200+ PPC landing pages](/blog/ppc-landing-page-conversion-lessons) are mostly about removing options, which a template fights you on.

**3. Control and longevity.** With a plugin stack you depend on every plugin author to keep updating. Custom code has fewer moving parts, but it also means you depend on a developer, so make sure the code is yours and documented.

**4. Accessibility and structure.** Clean headings, keyboard support and sensible markup are easier to guarantee when you write the markup. Many themes get this partly right and partly wrong. See the [screen reader accessibility checklist](/blog/screen-reader-accessibility-checklist) for what to test either way.

## A common myth: custom ranks better

Google ranks pages on content, links and page experience. It does not reward a site for being hand-coded. What custom gives you is a head start on the page-experience part (speed, layout stability, clean structure). You still need useful content and other sites linking to you.

## A quick way to decide

| If your situation is... | Lean towards |
| --- | --- |
| Simple brochure site, small budget, you will edit it | Template |
| Paid ads sending traffic to one page | Custom landing page |
| Slow mobile scores you cannot fix with settings | Custom, or a focused speed fix |
| You need unusual features or integrations | Custom |
| Not sure the business needs a site beyond a basic page | Template first |

## Cost: be careful with any single number

Prices vary widely by scope, so I do not quote a fixed figure here. The honest approach is to describe what you need and ask for a quote on that scope.

## What to ask before you hire anyone

1. Do I own the code and the design files when it is finished?
2. How will you measure speed, and on which devices?
3. What happens when something breaks after launch, and who fixes it?
4. Can I see live pages you built, not only screenshots?
